# 旅冊｜旅遊小冊製作器

把旅行行程排成可以列印、可以傳給旅伴的旅遊小冊。免安裝、免註冊。

- 行程資料只存在使用者自己的瀏覽器（IndexedDB），不會上傳到任何伺服器。唯一例外：「Google 地圖儲存清單匯入」會把清單分享連結交給本站的 Worker 去向 Google 取清單（不儲存、不送出行程）。換裝置請用「匯出 → 下載備份檔」。
- 可以加到手機主畫面（PWA），離線也能打開。
- 匯出：A5 列印／PDF、A4 對折小冊（騎馬釘）、可傳給旅伴的 HTML 小冊、送禮版、行事曆 .ics。

## 檔案

- `index.html`：整個 app（單一檔案）
- `manifest.webmanifest`、`sw.js`、`icons/`：加到主畫面與離線使用
- `tools/`：地點庫產生器（不會上傳）。`worker.js`、`wrangler.toml`、`.assetsignore`：Cloudflare Worker。靜態檔案照常由 Workers Static Assets 提供，另外只有一個 `/api/gmaps-place`（展開單一地點短網址，見下）

`index.html` 走「先連網、失敗才用快取」，所以有網路時使用者打開就會拿到新版，不用改 `sw.js`。只有改了圖示或 `manifest.webmanifest` 時，才需要把 `sw.js` 裡的 `VERSION` 加一號，讓舊的快取被清掉。

## Google「我的地圖」（My Maps）匯入（不需要 Worker）

在「儲存清單」同一個框貼上我的地圖的分享連結（網址含 `mid=`），或直接貼 KML 文字。瀏覽器直接讀 `https://www.google.com/maps/d/kml?mid=…&forcekml=1`：2026-11-08 實測 google.com/robots.txt 對 `User-agent: *` 有 `Allow: /maps/d/`，回應帶 `Access-Control-Allow-Origin: *`，所以不經過旅冊的 Worker。只匯入點狀地標（線、區域略過），帶入名稱、座標、說明與 ExtendedData（放進「小提醒」），地圖連結用官方 Maps URLs 格式 `maps/search/?api=1&query=緯,經`。地圖要設成「知道連結的任何人都能查看」。

## 檔案匯入（不需要網路、不上傳）

景點分頁「選擇檔案」可一次選多個：我的地圖匯出的 `.kml`／`.kmz`（`.kmz` 用瀏覽器內建的 `DecompressionStream('deflate-raw')` 解壓，`unzipAll`）、Google Takeout「已儲存」的清單 `.csv`（欄位 Title, Note, URL, Comment，每個檔案名＝清單名，顯示成圖層）或整包 `.zip`（讀裡面所有 `.csv`）、`Saved Places.json`（GeoJSON）。Takeout 清單 CSV 多半沒有座標，只帶名稱、備註與地圖連結；網址含逗號卻沒加引號的列會自動併回網址欄。KML 說明裡沒包 CDATA 的 `<br/>` 也會轉成換行。

## 單一地點短網址（需要 Worker）

「從 Google 地圖新增」貼完整網址時在瀏覽器裡直接解析名稱與座標；貼手機分享的 `maps.app.goo.gl` 短網址時，先新增景點，再呼叫 `GET /api/gmaps-place?u=…`。Worker 只讀轉址的 Location 標頭（最多 5 跳、每一跳都必須是 Google 地圖網域，不下載頁面），展開後從 `/maps/place/名稱/@緯,經` 或 `?q=名稱` 取名稱與座標回傳。讀不到就保留空白名稱讓使用者自己填。展開後網址的實際格式未在本機驗證（開發環境連不到 Google），部署後需要用真的短網址測一次。

## 每日行程 → 景點／住宿卡

每一行的連結選單有「把這行變成新景點」「把這行變成新住宿」。「每日」分頁上方的「把 N 行變成景點／住宿頁…」會列出所有還沒連結的行程，先猜好要變成什麼（`guessLink`）：同名的現有景點或住宿就直接連結；有「入住、飯店、hotel」的變成住宿；交通、取車還車、機場、吃飯這類一般行程預設不要；其他變成景點。名稱會去掉「入住」「前往」等字（`cleanItemName`）。新住宿的入住日是那一天，退房日是下一間住宿的入住日或回程日，前一間住宿若跨過這天，退房日會改成這天（`newStayAt`）。

## 購物清單合計

價格欄寫 `¥1,296`、`1296円`、`NT$300`、`300元` 都會被認出幣別加總；只寫數字的，目的地是日本（或沒選國家）當日圓，其他國家不算。最後一頁購物清單底部印「合計 N 項：¥… ＋ NT$…」，有填匯率時再換算成台幣，看不懂的價格會註明幾項沒算進去。編輯器「購物」分頁也會顯示目前合計。

## 每日「依時間排序」

沒填時間的項目跟著原本在它上面的那一項走（`12:00 午餐` 下面沒時間的「買咖啡」，排序後仍在午餐後面）；一天最上面就沒時間的留在最上面。

## 從 Google 地圖匯入多個地點（不經過伺服器）

2026-11 起移除「貼儲存清單連結、由 Worker 代讀」的做法（條款風險較高），只保留三種在使用者瀏覽器裡處理的方式：

1. **書籤小工具**（電腦，給「儲存清單」用）：在 Google 地圖打開清單時點書籤，程式在 google.com 自己的網域讀清單，帶著 `#gm=…`（[名稱, 地址, lat, lng, 備註, cid]）開回旅冊，`gmFromHash` 交給勾選視窗。仍屬灰色地帶：讀的是 Google 未公開的 getlist 路徑（robots.txt 目前 `Allow: /maps/preview`）。
2. **Google「我的地圖」**：貼分享連結（見下節），或選擇匯出的 KML／KMZ 檔。
3. **複製貼上**：電腦版清單欄 Ctrl+A 複製後貼上，`parseGmPageText` 只認出名稱。

貼上儲存清單的分享連結時，會跳出說明視窗引導改用以上方法。另外也接受 Google Takeout 的檔案（見「檔案匯入」）。
## 搜尋景點（維基百科）

景點分頁最上面的「搜尋景點」直接在瀏覽器查維基百科（`wsQuery`：`generator=search` 加 `coordinates|description|langlinks|pageprops`），先查中文（`variant=zh-tw`），有座標的結果少於 3 個再查日文，依名稱相似度排序、略過消歧義頁。中文條目沒有座標時（例：清水寺），用日文同一條目的座標補。加入時帶名稱、日文名、座標與地圖連結（官方 Maps URLs 格式），勾選時另外帶入維基導言並記錄 `descSrc`（CC BY-SA 4.0，自動印在圖文來源頁）。只涵蓋有維基條目的地點，店家餐廳多半查不到。

### 旅冊地點庫（自建，`poi/`）

`tools/build-poi.mjs`（Node 18 以上、不需安裝套件）從 OpenStreetMap 的 Overpass API 抓**日本 47 都道府縣**（`REGIONS`，`admin_level=4`；代號如 `tokyo`、`kyoto`、`okinawa`），每縣分四次查（餐飲／店家／景點住宿車站等／自然景點）。每次查詢宣告 `timeout:180`、不加 `maxsize`（宣告越大，忙碌時越晚排到）；三台公開伺服器輪流用（overpass-api.de、overpass.private.coffee、overpass.osm.jp，見 [OSM wiki](https://wiki.openstreetmap.org/wiki/Overpass_API#Public_Overpass_API_instances)）。整縣查不動（504、逾時、記憶體不夠）時，把該縣邊界框切成四塊分開查，最多切 3 層（64 塊）；三台都只回「忙」就等 2 分鐘再試；連續 15 次失敗就整個停下，晚點重跑會接著做。收景點、寺社、博物館、公園、車站、住宿、餐廳、咖啡甜點、店家，以及有 Wikidata 的自然景點（湖、瀑布、山、溪谷、海灘、島、國立公園等）（排除美髮、修車、洗衣、便利商店等觀光客用不到的類型，也排除沒有 Wikidata 的路邊石碑與鐵路路線），再用 Wikidata 補繁體中文名稱，沒有的話把 OSM 的 `name:zh` 用 OpenCC 對照表轉成繁體。同名且相距 60 公尺內的視為同一筆。輸出：

- `poi/<縣代號>.json`：`rows` 每筆 `[名稱, 日文名, 繁中名, 英文名, 緯度, 經度, 類別, 細類, 區, 地址, 營業時間(OSM 格式), Wikidata, 平假名/別名]`；範圍 `bbox` 取 0.5%～99.5% 的點（離島照收，但不撐大範圍）
- `poi/index.json`：地區清單與範圍（每做完一縣就存一次）；`poi/norm.json`：搜尋用的字形對照；`poi/LICENSE.txt`
- `tools/cache/`：Overpass 原始回應（不會上傳）

在網站資料夾執行 `node tools/build-poi.mjs`：只做還沒做過的縣，中斷後再跑同一行會接著做；`node tools/build-poi.mjs tokyo` 只重做一縣；`--all` 全部重抓。第一次做完全日本預估 1～2 小時（推估，依 Overpass 忙碌程度）。舊版以「市」為單位的檔案（kobe…）會被自動清掉。跑完再 `npx wrangler deploy`。建議每 1～3 個月更新一次。

`node tools/build-poi.mjs --upgrade`：把舊版產生器做的縣升級成新格式（補電話、網站、自然景點、機場）。已下載的 `tools/cache/<縣>.osm.json` 會沿用，只補抓「自然景點與機場」那一類（下載檔標 `v:2` 表示四類都齊了，之後升級只重新整理不再下載）；已經是新格式的縣跳過，中斷後再跑會接著做。

**電話、網站、介紹**：產生器把 OSM 的 `phone`／`contact:phone` 與 `website`／`contact:website`／`url`（只收 http(s)，多個取第一個）存成每筆的第 14、15 欄（`cols` 末兩欄 `phone`、`web`）；舊檔沒有這兩欄也能讀。從地點庫加入景點時一起帶入，景點多了「電話」「網站」欄位，小冊景點頁與數位版都會顯示（數位版可直接撥號、開網站）。地點有 Wikidata 編號時，加入後用編號查對應的維基百科條目（中文→日文→英文），自動帶入導言並標示 CC BY-SA 來源；已經寫了介紹的不會覆蓋。實測比例（OSM 原始資料）：京都約 8% 有電話、12% 有網站。電話加入時統一成日本國內格式（`fmtJpPhone`）：`+81`／`81` 開頭改成 `0`；手機、0120、東京 03、大阪 06 與 `JP_AC3` 列出的主要城市 3 位數區碼會加連字號，其他區碼長度不一，只轉成 0 開頭不斷開（原本就有分隔的保留）。

**台灣俗稱**：`index.html` 的 `POI_ALIAS` 把台灣常用叫法對到 OpenStreetMap 上的日文名（環球影城→ユニバーサル・スタジオ・ジャパン、唐吉訶德→ドン・キホーテ、竹林小徑→嵐山竹林、二年坂→二寧坂…）。輸入含左邊的詞就也用右邊找，較長的俗稱優先。輸入以「車站／站／駅」結尾時，會去掉這幾個字再找並讓車站排前面（京都車站→京都）。新增俗稱後執行 `node tools/check-alias.mjs`，會列出每個日文名在地點庫裡找不找得到（✔ 找得到、△ 只有名稱包含它的、✖ 找不到）。

2026-11-09 第一次以「市」為單位產生（京都市 9,771、大阪市 20,588、奈良市 2,203、神戸市 7,157 筆，合計約 3.2 MB）。`poi/` 與 `tools/cache/` 不進 git，各自在部署的電腦上產生。

**目的地**：建立新行程時先問「這趟要去哪裡？」（熱門城市＋47 都道府縣，可多選、可跳過；第一次使用時等使用說明看完才問）。選了就存 `t.regions`（縣代號）與 `t.cities`（熱門城市名），並設定國家＝日本、時區＝+9、封面英文字（一兩個城市時，例：KYOTO & OSAKA）、空白標題（例：京都・大阪之旅）。「基本」分頁可以改。

網站端（`poiSearch`）：先載入行程選的目的地與行程地點所在的縣（`poiPick`）；都沒有就不載入，提示先選目的地（全日本太大）。第一層找不到好結果（最高分低於 80）時，再載入旁邊的縣（範圍外擴 0.3 度內，`poiNear`），所以住京都也搜得到奈良東大寺。在瀏覽器裡比對；比對前把日文新字體與簡體都轉成同一寫法、片假名轉平假名，所以「伏見稻荷」「京都タワー」「kyoto tower」都找得到。顯示名稱：原名有假名才用繁中名（京都タワー→京都塔），純漢字的用原名轉繁體字形（金閣寺不會變成 Wikidata 的「鹿苑寺」）。排序：名稱完全相同＞開頭相同＞包含；觀光類（景點、主題樂園、寺社、博物館、公園、市場）加分，車站、住宿、紀念碑減分，別名或讀音比對到的排後面。輸入類型（毛線、二手、藥妝、伴手禮…）會列出那一類店家，並用日文常見寫法再比一次（毛線→毛糸、拉麵→ラーメン，`POI_SYN`／`POI_TY`）。搜尋順序：地點庫 → 維基百科 →（使用者按了才查）Nominatim。加入時帶名稱（有繁中名就用繁中，日文原名放日文名）、座標、區、地址、營業時間（轉成中文星期）、類別，記錄 `locSrc:'osm'` 以便在圖文來源頁標示。`poi/` 在 service worker 裡走網路優先，更新後不會卡舊版。

授權：`poi/*.json` 是 OpenStreetMap 的衍生資料庫，依 ODbL 必須同樣以 ODbL 公開並標示 © OpenStreetMap contributors（檔案內與 `poi/LICENSE.txt` 已寫明）；印出的小冊屬於「作品」，在圖文來源頁標示即可。`tools/cjk-map.json` 由 OpenCC（Apache-2.0）的轉換表產生。

維基百科結果依名稱相似度排序（完全相同、包含、兩字一組重疊比例；也比對重新導向的名稱，例如「金閣寺」→鹿苑寺）。相似度低於 0.45 的收進預設收合的「其他名稱不太相符的結果」，例外是維基搜尋排第一且有座標的條目。已選目的地但該縣的地點庫還沒建好時，提示會寫出縣名並說明這次只查維基百科。

### 查 OpenStreetMap（店家、餐廳）

維基查不到時，使用者按「查 OpenStreetMap」才會呼叫公開的 Nominatim（`osmSearch`）。依 Nominatim 使用規範（全部使用者合計每秒最多 1 次、不得做自動完成），只由按鈕觸發，並在本機排隊至少間隔 1.1 秒；帶 `countrycodes`（目的地國家）與 `viewbox`（行程已有景點的範圍，偏好但不限制）。加入時帶名稱、日文名（`name:ja`）、座標、地區、地址、類別，並記錄 `locSrc:'osm'`；圖文來源頁與手機閱讀版會列出這些地點並印出「© OpenStreetMap contributors，ODbL，https://www.openstreetmap.org/copyright」。實測（2026-11-08）：「一蘭 道頓堀」查得到；「中村藤吉 本店」會找到同名不同店，所以介面提醒使用者確認。用量變大時要改成自架或付費的 Nominatim。

## 景點介紹：維基百科導言（文字 CC BY-SA 4.0）

景點分頁每個景點有「從維基百科找導言」，批次整理也有「缺介紹的找維基百科」。瀏覽器直接呼叫 Wikipedia API（`origin=*`，帶 `Api-User-Agent`），不經伺服器：先用座標 `list=geosearch`（400 m）找附近條目，再用 `list=search&srwhat=nearmatch` 以名稱核對；名稱對得上（`wpScore` ≥ 0.8）才算確定，座標附近但名稱不符的只列為「不確定」候選，批次模式不採用。語言順序依名稱字元決定（中文→日文→英文、假名→日文優先、拉丁字母→英文優先）；中文版用 `variant=zh-tw` 取繁體。導言取前幾句、去掉讀音括號，約 120–190 字。

來源記在 `places[].descSrc`（site、title、url、license、at）。景點頁介紹下方印一行來源，小冊最後自動加「圖文來源」頁（`credits`，有來源才出現、不可關閉），數位閱讀版也有同名區塊。把介紹清空會一併清掉來源；範本匯出保留 `descSrc`。介紹留白的景點，頁面改印「現場筆記」橫線區。

Wikimedia 2026 年起對匿名瀏覽器請求限流：所有請求序列進行，批次每筆間隔 250 ms，遇 429 依 `Retry-After` 停止並提示。店家、小景點通常沒有條目，這是預期中的限制。

## 版型「和紅」（beni）

深紅、深灰資訊頁＋米色行程頁，標題用 Noto Serif TC，英文與數字用 Cormorant Garamond（Google Fonts，OFL），風格參考雜誌式手排旅遊小冊。

- 每頁底色依頁面種類決定：`renderPages` 在版型 `decorate` 之後，於每頁 `<section>` 加上 `data-k="<頁面種類>"`（放在 decorate 之後，抹茶版型 `mtDecorate` 對 `<section class="pg cover">` 的判斷不受影響）。深紅：封面、出發資訊、路線、住宿、合集、景點速查；深灰：打包、預約、預算、緊急資訊；其餘米色。黑白省墨（`.mono`）時全部回到白底。
- 封面：`opts.bcover` 為 `frame`（相框）或 `full`（滿版）；上方英文大字取 `t.coverEn`，留空依國家帶入（JAPAN、KOREA…），字級依字數自動縮小；下方 Travel Itinerary＋標題＋日期。
- 每日頁：`Day 1`＋地區、右上 `11.19`＋曜日印章（日本行程用「木曜日」，其他用「星期四」），每日照片變成右側淡化背景。
- 主題色：`cvars` 在和紅時另外輸出 `--bd`（深色頁底，`deepHex(c,.3)`：HSL 亮度上限 0.3、飽和度上限 0.5）、`--bink`（米色頁內文，亮度上限 0.2）、`--bmute`。所以換任何主題色，深色頁和文字都會跟著變，而且一定夠深、米色字讀得清楚。版型可帶 `palette`（推薦配色），編輯器會顯示有名稱的色票：深紅、藍染、抹茶、焦茶、墨、葡萄。
- 這些元素（`.cv-en`、`.cv-mon`、`.cv-ti`、`.bh`）所有版型都會輸出但預設隱藏；已用舊版逐像素比對，其他版型畫面不變。

## 移動時間概估與手機編輯（2026-11-09）

- **移動時間概估**（`travelEst`）：前後兩項都連結了有座標的景點或住宿時，每日行程該項下方顯示「距上一站約 X 公里・步行約 N 分／大眾運輸約 N 分（概估）」；自己填了交通就不顯示。算法只用直線距離（乘 1.3）：步行 4.5 km/h；大眾運輸 12 分 + 28 km/h；40 公里以上 20 分 + 80 km/h。不查路線、班次、轉乘，只供參考。
- **行程檢查**：兩站時間差（上一站有結束時間就從結束算）比概估移動時間還短時提醒。
- **手機編輯**：600px 以下每日行程收掉上下箭頭（用 ⠿ 拖曳排序），文字欄變寬，每項高度約減半。

## 時間格式與行程檢查

- 時間欄接受 `09:30` 或區間 `09:00–11:00`（`-` `–` `~` `〜` `至` `到` 都可）。分鐘必須 00–59；小時 0–29，24 以上代表過午夜（`25:30`＝隔天 1:30）；區間結束早於開始也視為過午夜。`hm` 取開始、`hmEnd` 取結束，超出範圍回 null（不再把 `25:99` 算成 26:39）。
- `tripChecks` 新增：有結束時間的項目和之後開始的項目重疊時警告；時間不存在（`25:99`）警告；看不懂的時間（例如「早上」）提示會被排序、重疊檢查、今日模式略過。編輯器裡不存在的時間會標紅。
- 小冊每日頁的區間時間：開始時間大字、結束時間小字在下一行。行事曆（ICS）有結束時間就用結束時間。

## 景點頁順序

`opts.placeSort` 預設 `visit`：景點介紹頁、合集頁裡的店、精簡模式的速查表、數位閱讀版都依「第一次出現在行程的第幾天、那天第幾項」排序（`visitOrder`）；沒排進行程但設成一律印的景點放最後，保留景點分頁的順序。改成 `list` 就照景點分頁的清單順序。合集頁放在該組第一間店的位置。

## 每日頁：交通段與類型圖示

- 交通欄（`items[].transport`）改成多行。任何一行有 `｜` 或 `|` 就當成分段：`路線｜起站→迄站｜班距、車廂、票價｜出口或路標`，每段印成「路線色塊＋（起站 → 迄站）資訊＋第二行路標」；沒有分隔符號的舊寫法照原樣顯示。編輯器有「＋ 加一段轉乘」小表單（路線欄帶出已知路線），按下會把格式化好的一行加到交通欄。數位閱讀版、今日模式、收合摘要用 `legsPlain` 轉成一行文字。
- 路線色（`LINES`）只收錄色名有查證的路線：Osaka Metro 御堂筋（紅）、谷町（紫）、四つ橋（藍）、中央（綠）、千日前（粉）、堺筋（茶）；東京 Metro＋都營 13 線；阪急神戸（藍）、宝塚（橙）、京都（綠）線；JR京都線、JR神戸線（藍，神戶新聞 2022 報導 JR 西日本定的線色）、大阪環状線（橘）。色碼是依色名取的近似值。中央線、東西線同名不同城市，依當天地區／標題判斷東京或大阪；判斷不出來或沒收錄的路線（京都地鐵、京阪、南海、JR 其他線…）用主題色。
- 類型圖示：連結景點用 `placeCat`，連結住宿或自動入住退房用床，其餘用 `detectCat(文字)`；飛機、床、地點、餐具、咖啡、購物、電車七種線條圖示。`opts.tlIcons` 為 null 時只有和紅版型顯示，頁面分頁可手動開關（所有版型都可用）。有交通段的項目，圖示下方會畫一條直線連到下一站。

## 景點分組（合集頁）與付款標籤

`places[].group`：同一組有 2 個以上要印的景點時，`buildPages` 用 `pushPlace` 把它們排成合集頁（`k:'coll'`），一頁最多 4 間、平均分配（4→1 頁、5→3＋2、7→4＋3），放在該組第一個景點原本的位置（`placeOrder:'after-day'` 時就是第一次去的那天之後）。每間：照片或插圖（左右交錯）、名稱、地區、DAY、付款標籤、介紹（最多 4 行，4 間時 3 行）、營業／公休／費用、地址、小提醒、QR、照片與文字來源。頁碼參照（每日頁的 P.xx）指向合集頁。精簡模式仍用景點速查表。景點分頁有分組輸入（datalist 帶出已有分組）和批次「設成這一組」。

自動合集（`opts.autoGroup`，預設開）：沒填分組的景點，分類是餐廳／咖啡（`food`/`cafe`）就歸「吃吃喝喝」、購物（`shop`）歸「購物」，同樣要 2 個以上要印的才成頁。分類用手選的「插圖分類」，沒選就只看名稱判斷（不看地區，避免地區寫「心齋橋」的景點都被當成購物）。分組填 `-` 表示這個景點單獨一頁。景點清單的分組小標籤用虛線框標示自動分組。「頁面」分頁可以關掉。

`places[].pay`：`cash`（只收現金）、`card`、`ic`、`qr`、`tax`（可退稅），使用者自己查了勾選，印成小標籤（只收現金特別標色）；景點頁、合集頁、速查表、數位閱讀版、今日模式都會顯示。購物卡片也會印出 `shops[].note`（最多 2 行）。

## 移動文字（拖曳）

預覽上方勾「移動文字」後，封面的每一行字（英文大字、月份、Travel Itinerary、標題、副標題、日期、統計、同行者）和合集頁、自訂頁的標題會出現虛線框，可以拖曳；點兩下回原位，「全部回原位」一次清掉。位置存在 `t.pos`（`'頁鍵|元素': [x, y]`，頁面座標 px，±900 內），輸出時用 CSS `translate` 位移，不影響排版流，所以其他內容不會被推動、自動分頁也不受影響。拖曳範圍限制在頁面內。預覽、A5、A4 對折都用同一份 HTML，位置一致。每日頁、景點頁這類會依內容自動分頁的頁面不開放拖曳。範本只保留封面的位置。

和紅「相框」封面預設把英文大字和月份移到照片上方，不再疊在照片上（淺色照片會看不清楚）；「滿版照片」維持疊在照片上。

## 出發資訊頁：登機證樣式

`opts.flightCard`（預設開）：每筆航班／長途交通印成登機證樣式的卡片。「出發」「抵達」裡有 3 個大寫英文字母（例：`桃園 TPE T1`）就把代碼放大，剩下的字當小字；沒有代碼就直接印地名。時間寫 `06:50–10:15` 會分成 DEPART／ARRIVE。班次像航班號（`IT 210`）或有機場代碼時標 BOARDING PASS，否則標 TICKET（新幹線等）。右邊的條碼只是裝飾，不能掃。關掉就回到原本的文字列表。

## 景點照片：Wikimedia Commons

景點分頁每個景點的照片欄有「從 Wikimedia Commons 找照片」。瀏覽器直接呼叫 Commons API（同樣序列請求、遵守 429 Retry-After）：座標 `list=geosearch`（400 m）＋名稱搜尋 `"名稱" filetype:bitmap`（有日文名再搜一次），用 `imageinfo/extmetadata` 讀授權。

## 資料版本（schema）

每份行程都存有 `schema` 版本號（目前是 2）。要改資料結構時：

1. 把 `index.html` 裡的 `SCHEMA` 加一。
2. 在 `MIGRATE` 加一個步驟，鍵是「從哪一版升上來」，例如 `2:t=>{ /* 把舊欄位改成新欄位 */ }`。
3. 新欄位的預設值寫在 `normalize()`。

讀取或匯入時會依序跑完升級步驟。如果瀏覽器裡有比程式還新的資料（例如舊的快取頁面打開了新版存的資料），程式會暫停儲存並提示重新整理，避免蓋掉資料。

## 停留時間與查路線（2026-11-12）

- **停留多久**：每日行程的每一項展開後有「停留多久」選單（30 分～4 小時）。選了會把時間欄寫成 `10:30–12:00` 這樣的範圍（原本就支援手打範圍，這只是比較好填）；選「不指定」就拿掉結束時間。要先填開始時間。有結束時間的那一行時間欄會自動加寬，收合時顯示「停留 1 小時 30 分」。
- 有結束時間後，原有的檢查才會完整生效：時間重疊、「上一站結束後只隔 N 分，但移動概估要 M 分」、行事曆（.ics）的結束時間。
- 新增行程的預設時間（`nextTime`）：最晚的一項有結束時間就用「結束 + 30 分」，沒有才用「開始 + 90 分」。
- **查路線 ↗**（`routeURL`）：前後兩項都連結了景點或住宿時，該項下方多一個連結，開 Google 地圖「上一站 → 這一站」的大眾運輸路線（班次、時間、票價由 Google 提供）。只是一般網址（`google.com/maps/dir/?api=1&origin=…&destination=…&travelmode=transit`），不用金鑰、不經過伺服器。有座標用座標，沒有就用名稱＋地址。
- 今日模式的「下一站」卡多一顆「從這裡怎麼去」：不帶起點，Google 地圖會用手機目前位置。
