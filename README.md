# 旅冊｜旅遊小冊製作器

把旅行行程排成可以列印、可以傳給旅伴的旅遊小冊。免安裝、免註冊。

- 行程資料只存在使用者自己的瀏覽器（IndexedDB），不會上傳到任何伺服器。唯一例外：「Google 地圖儲存清單匯入」會把清單分享連結交給本站的 Worker 去向 Google 取清單（不儲存、不送出行程）。換裝置請用「匯出 → 下載備份檔」。
- 可以加到手機主畫面（PWA），離線也能打開。
- 匯出：A5 列印／PDF、A4 對折小冊（騎馬釘）、可傳給旅伴的 HTML 小冊、送禮版、行事曆 .ics。

## 檔案

- `index.html`：整個 app（單一檔案）
- `manifest.webmanifest`、`sw.js`、`icons/`：加到主畫面與離線使用
- `worker.js`、`wrangler.toml`、`.assetsignore`：Cloudflare Worker。靜態檔案照常由 Workers Static Assets 提供，另外多一個 `/api/gmaps-list`（見下）

`index.html` 走「先連網、失敗才用快取」，所以有網路時使用者打開就會拿到新版，不用改 `sw.js`。只有改了圖示或 `manifest.webmanifest` 時，才需要把 `sw.js` 裡的 `VERSION` 加一號，讓舊的快取被清掉。

## Google「我的地圖」（My Maps）匯入（不需要 Worker）

在「儲存清單」同一個框貼上我的地圖的分享連結（網址含 `mid=`），或直接貼 KML 文字。瀏覽器直接讀 `https://www.google.com/maps/d/kml?mid=…&forcekml=1`：2026-11-08 實測 google.com/robots.txt 對 `User-agent: *` 有 `Allow: /maps/d/`，回應帶 `Access-Control-Allow-Origin: *`，所以不經過旅冊的 Worker。只匯入點狀地標（線、區域略過），帶入名稱、座標、說明與 ExtendedData（放進「小提醒」），地圖連結用官方 Maps URLs 格式 `maps/search/?api=1&query=緯,經`。地圖要設成「知道連結的任何人都能查看」。

## 單一地點短網址（需要 Worker）

「從 Google 地圖新增」貼完整網址時在瀏覽器裡直接解析名稱與座標；貼手機分享的 `maps.app.goo.gl` 短網址時，先新增景點，再呼叫 `GET /api/gmaps-place?u=…`。Worker 只讀轉址的 Location 標頭（最多 5 跳、每一跳都必須是 Google 地圖網域，不下載頁面），展開後從 `/maps/place/名稱/@緯,經` 或 `?q=名稱` 取名稱與座標回傳。讀不到就保留空白名稱讓使用者自己填。展開後網址的實際格式未在本機驗證（開發環境連不到 Google），部署後需要用真的短網址測一次。

## 每日行程 → 景點／住宿卡

每一行的連結選單有「把這行變成新景點」「把這行變成新住宿」。「每日」分頁上方的「把 N 行變成景點／住宿頁…」會列出所有還沒連結的行程，先猜好要變成什麼（`guessLink`）：同名的現有景點或住宿就直接連結；有「入住、飯店、hotel」的變成住宿；交通、取車還車、機場、吃飯這類一般行程預設不要；其他變成景點。名稱會去掉「入住」「前往」等字（`cleanItemName`）。新住宿的入住日是那一天，退房日是下一間住宿的入住日或回程日，前一間住宿若跨過這天，退房日會改成這天（`newStayAt`）。

## 購物清單合計

價格欄寫 `¥1,296`、`1296円`、`NT$300`、`300元` 都會被認出幣別加總；只寫數字的，目的地是日本（或沒選國家）當日圓，其他國家不算。最後一頁購物清單底部印「合計 N 項：¥… ＋ NT$…」，有填匯率時再換算成台幣，看不懂的價格會註明幾項沒算進去。編輯器「購物」分頁也會顯示目前合計。

## 每日「依時間排序」

沒填時間的項目跟著原本在它上面的那一項走（`12:00 午餐` 下面沒時間的「買咖啡」，排序後仍在午餐後面）；一天最上面就沒時間的留在最上面。

## 從 Google 地圖「儲存清單」匯入景點（需要 Worker）

匯進來的景點預設是「收藏」：`places[].book` 為 `''`（自動：排進某一天才印）、`'yes'`（一律印）、`'no'`（不印）。`buildPages` 依此把未收錄的景點加進 `hidden`，景點頁、景點速查、目的地卡、數位閱讀版都一致。景點分頁有「批次整理」：勾選多個景點後一次排進某天、改收錄狀態或刪除。

重複判斷（`gmHave`）：同 Google CID → 同一間；否則名稱相同且任一方沒座標或相距 300 公尺內 → 同一間；同名但距離很遠視為不同分店。

`sw.js` 對 `/api/` 不做快取（Cache API 不會看 Cache-Control 到期，否則重新匯入會拿到舊清單）。`node --test test/worker.test.mjs` 用固定回應片段驗證解析器，Google 改格式時會先紅。

景點分頁可以貼上 Google 地圖清單的分享連結（`maps.app.goo.gl/…`），一次把清單裡的地點勾選匯入（名稱、地址、座標、清單備註）。

瀏覽器做不到這件事：清單頁是 JS 動態載入，Google 的清單 API（`/maps/preview/entitylist/getlist`）沒有 CORS 標頭，短網址的轉址也看不到。所以由 `worker.js` 代讀：解短網址 → 取清單 id（`!2s…` 或 `/placelists/list/…`）→ 呼叫 getlist → 回傳精簡 JSON（含 `Access-Control-Allow-Origin: *`，資料本來就是公開分享的清單）。Worker 只接受 Google 地圖的網址，不是通用代理。

部署：`npx wrangler deploy`（會同時上傳靜態檔案與 Worker）。app 預設打 `https://travel-book.jim99725.workers.dev/api/gmaps-list`；自架的人可在瀏覽器 console 設 `localStorage.setItem('tabisatsu.gmproxy','https://你的.workers.dev/api/gmaps-list')`。

方法三（電腦、最穩）：景點分頁有一個可拖到書籤列的「匯入旅冊」書籤小工具。它在 Google 地圖清單頁執行，因為跟 Google 同源所以沒有 CORS 問題、也不經過任何伺服器；抓到清單後帶著 `#gm=<base64 JSON>` 開啟旅冊，旅冊啟動時看到 `#gm=` 就跳出勾選框（資料不會留在網址列，讀完就清掉）。

沒有 Worker（GitHub Pages、離線）時的方法二：電腦版 Google 地圖打開清單，在清單欄 Ctrl+A 全選、複製，貼到同一個框，只會得到名稱與類別。

已知限制：一次最多讀 500 個（`!4i500`）。Google 對 Cloudflare 機房 IP 會回 429（實測 2026-11 如此），Worker 會依序換 `www.google.com`、`maps.google.com`、`www.google.com.tw`、`www.google.co.jp` 再試；全被擋時 app 會提示改用方法三或方法二。`/api/gmaps-list?u=…&debug=1` 會多回 `via`（成功的主機）與 `tried`。

## 景點介紹：維基百科導言（文字 CC BY-SA 4.0）

景點分頁每個景點有「從維基百科找導言」，批次整理也有「缺介紹的找維基百科」。瀏覽器直接呼叫 Wikipedia API（`origin=*`，帶 `Api-User-Agent`），不經伺服器：先用座標 `list=geosearch`（400 m）找附近條目，再用 `list=search&srwhat=nearmatch` 以名稱核對；名稱對得上（`wpScore` ≥ 0.8）才算確定，座標附近但名稱不符的只列為「不確定」候選，批次模式不採用。語言順序依名稱字元決定（中文→日文→英文、假名→日文優先、拉丁字母→英文優先）；中文版用 `variant=zh-tw` 取繁體。導言取前幾句、去掉讀音括號，約 120–190 字。

來源記在 `places[].descSrc`（site、title、url、license、at）。景點頁介紹下方印一行來源，小冊最後自動加「圖文來源」頁（`credits`，有來源才出現、不可關閉），數位閱讀版也有同名區塊。把介紹清空會一併清掉來源；範本匯出保留 `descSrc`。介紹留白的景點，頁面改印「現場筆記」橫線區。

Wikimedia 2026 年起對匿名瀏覽器請求限流：所有請求序列進行，批次每筆間隔 250 ms，遇 429 依 `Retry-After` 停止並提示。店家、小景點通常沒有條目，這是預期中的限制。

## 版型「和紅」（beni）

深紅、深灰資訊頁＋米色行程頁，標題用 Noto Serif TC，英文與數字用 Cormorant Garamond（Google Fonts，OFL），風格參考雜誌式手排旅遊小冊。

- 每頁底色依頁面種類決定：`renderPages` 在版型 `decorate` 之後，於每頁 `<section>` 加上 `data-k="<頁面種類>"`（放在 decorate 之後，抹茶版型 `mtDecorate` 對 `<section class="pg cover">` 的判斷不受影響）。深紅：封面、出發資訊、路線、住宿、合集、景點速查；深灰：打包、預約、預算、緊急資訊；其餘米色。黑白省墨（`.mono`）時全部回到白底。
- 封面：`opts.bcover` 為 `frame`（相框）或 `full`（滿版）；上方英文大字取 `t.coverEn`，留空依國家帶入（JAPAN、KOREA…），字級依字數自動縮小；下方 Travel Itinerary＋標題＋日期。
- 每日頁：`Day 1`＋地區、右上 `11.19`＋曜日印章（日本行程用「木曜日」，其他用「星期四」），每日照片變成右側淡化背景。
- 主題色：`cvars` 在和紅時另外輸出 `--bd`（深色頁底，`deepHex(c,.3)`：HSL 亮度上限 0.3、飽和度上限 0.5）、`--bink`（米色頁內文，亮度上限 0.2）、`--bmute`。所以換任何主題色，深色頁和文字都會跟著變，而且一定夠深、米色字讀得清楚。版型可帶 `palette`（推薦配色），編輯器會顯示有名稱的色票：深紅、藍染、抹茶、焦茶、墨、葡萄。
- 這些元素（`.cv-en`、`.cv-mon`、`.cv-ti`、`.bh`）所有版型都會輸出但預設隱藏；已用舊版逐像素比對，其他版型畫面不變。

## 時間格式與行程檢查

- 時間欄接受 `09:30` 或區間 `09:00–11:00`（`-` `–` `~` `〜` `至` `到` 都可）。分鐘必須 00–59；小時 0–29，24 以上代表過午夜（`25:30`＝隔天 1:30）；區間結束早於開始也視為過午夜。`hm` 取開始、`hmEnd` 取結束，超出範圍回 null（不再把 `25:99` 算成 26:39）。
- `tripChecks` 新增：有結束時間的項目和之後開始的項目重疊時警告；時間不存在（`25:99`）警告；看不懂的時間（例如「早上」）提示會被排序、重疊檢查、今日模式略過。編輯器裡不存在的時間會標紅。
- 小冊每日頁的區間時間：開始時間大字、結束時間小字在下一行。行事曆（ICS）有結束時間就用結束時間。

## 景點頁順序

`opts.placeSort` 預設 `visit`：景點介紹頁、合集頁裡的店、精簡模式的速查表、數位閱讀版都依「第一次出現在行程的第幾天、那天第幾項」排序（`visitOrder`）；沒排進行程但設成一律印的景點放最後，保留景點分頁的順序。改成 `list` 就照景點分頁的清單順序。合集頁放在該組第一間店的位置。

## 每日頁：交通段與類型圖示

- 交通欄（`items[].transport`）改成多行。任何一行有 `｜` 或 `|` 就當成分段：`路線｜起站→迄站｜班距、車廂、票價｜出口或路標`，每段印成「路線色塊＋（起站 → 迄站）資訊＋第二行路標」；沒有分隔符號的舊寫法照原樣顯示。編輯器有「＋ 加一段轉乘」小表單（路線欄帶出已知路線），按下會把格式化好的一行加到交通欄。數位閱讀版、今日模式、收合摘要用 `legsPlain` 轉成一行文字。
- 路線色（`LINES`）只收錄色名有查證的路線：Osaka Metro 御堂筋（紅）、谷町（紫）、四つ橋（藍）、中央（綠）、千日前（粉）、堺筋（茶）；東京 Metro＋都營 13 線；阪急神戸（藍）、宝塚（橙）、京都（綠）線；JR京都線、JR神戸線（藍，神戶新聞 2022 報導 JR 西日本定的線色）、大阪環状線（橘）。色碼是依色名取的近似值。中央線、東西線同名不同城市，依當天地區／標題判斷東京或大阪；判斷不出來或沒收錄的路線（京都地鐵、京阪、南海、JR 其他線…）用主題色。
- 類型圖示：連結景點用 `placeCat`，連結住宿或自動入住退房用床，其餘用 `detectCat(文字)`；飛機、床、地點、餐具、咖啡、購物、電車七種線條圖示。`opts.tlIcons` 為 null 時只有和紅版型顯示，頁面分頁可手動開關（所有版型都可用）。有交通段的項目，圖示下方會畫一條直線連到下一站。

## 景點分組（合集頁）與付款標籤

`places[].group`：同一組有 2 個以上要印的景點時，`buildPages` 用 `pushPlace` 把它們排成合集頁（`k:'coll'`），一頁最多 4 間、平均分配（4→1 頁、5→3＋2、7→4＋3），放在該組第一個景點原本的位置（`placeOrder:'after-day'` 時就是第一次去的那天之後）。每間：照片或插圖（左右交錯）、名稱、地區、DAY、付款標籤、介紹（最多 4 行，4 間時 3 行）、營業／公休／費用、地址、小提醒、QR、照片與文字來源。頁碼參照（每日頁的 P.xx）指向合集頁。精簡模式仍用景點速查表。景點分頁有分組輸入（datalist 帶出已有分組）和批次「設成這一組」。

自動合集（`opts.autoGroup`，預設開）：沒填分組的景點，分類是餐廳／咖啡（`food`/`cafe`）就歸「吃吃喝喝」、購物（`shop`）歸「購物」，同樣要 2 個以上要印的才成頁。分類用手選的「插圖分類」，沒選就只看名稱判斷（不看地區，避免地區寫「心齋橋」的景點都被當成購物）。分組填 `-` 表示這個景點單獨一頁。景點清單的分組小標籤用虛線框標示自動分組。「頁面」分頁可以關掉。

`places[].pay`：`cash`（只收現金）、`card`、`ic`、`qr`、`tax`（可退稅），使用者自己查了勾選，印成小標籤（只收現金特別標色）；景點頁、合集頁、速查表、數位閱讀版、今日模式都會顯示。購物卡片也會印出 `shops[].note`（最多 2 行）。

## 移動文字（拖曳）

預覽上方勾「移動文字」後，封面的每一行字（英文大字、月份、Travel Itinerary、標題、副標題、日期、統計、同行者）和合集頁、自訂頁的標題會出現虛線框，可以拖曳；點兩下回原位，「全部回原位」一次清掉。位置存在 `t.pos`（`'頁鍵|元素': [x, y]`，頁面座標 px，±900 內），輸出時用 CSS `translate` 位移，不影響排版流，所以其他內容不會被推動、自動分頁也不受影響。拖曳範圍限制在頁面內。預覽、A5、A4 對折都用同一份 HTML，位置一致。每日頁、景點頁這類會依內容自動分頁的頁面不開放拖曳。範本只保留封面的位置。

和紅「相框」封面預設把英文大字和月份移到照片上方，不再疊在照片上（淺色照片會看不清楚）；「滿版照片」維持疊在照片上。

## 出發資訊頁：登機證樣式

`opts.flightCard`（預設開）：每筆航班／長途交通印成登機證樣式的卡片。「出發」「抵達」裡有 3 個大寫英文字母（例：`桃園 TPE T1`）就把代碼放大，剩下的字當小字；沒有代碼就直接印地名。時間寫 `06:50–10:15` 會分成 DEPART／ARRIVE。班次像航班號（`IT 210`）或有機場代碼時標 BOARDING PASS，否則標 TICKET（新幹線等）。右邊的條碼只是裝飾，不能掃。關掉就回到原本的文字列表。

## 景點照片：Wikimedia Commons

景點分頁每個景點的照片欄有「從 Wikimedia Commons 找照片」。瀏覽器直接呼叫 Commons API（同樣序列請求、遵守 429 Retry-After）：座標 `list=geosearch`（400 m）＋名稱搜尋 `"名稱" filetype:bitmap`（有日文名再搜一次），用 `imageinfo/extmetadata` 讀授權。

只收 CC0、公有領域、CC BY、CC BY-SA；NC、ND、GFDL-only、授權不明、作者不明（非 CC0/PD）、標記 personality 限制、寬度 < 800、非點陣圖一律排除。照片座標多半是相機位置，所以距離只當加分；標題／描述含景點名稱才算確定，其餘標「不確定」。最多列 6 張讓使用者選，不做自動批次。

選用後下載 1280px 縮圖走 `compress()` 存成 data URL（和自己上傳的一樣），授權記在 `places[].photoSrc`（title、url、author、license、licenseUrl）。景點頁頁底印「照片：作者／Wikimedia Commons，授權」（照片在第一頁、文字來源在最後一頁），「圖文來源」頁分「照片」「文字」兩區並列出授權條款網址，註明照片經裁切；數位閱讀版同。自己上傳或移除照片會清掉 `photoSrc`。



- QR code 產生：[qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator)（Kazuhiko Arase，MIT License）。"QR Code" 是 DENSO WAVE INCORPORATED 的註冊商標。

## 美術素材（design-v1）

介面素材放在 `assets/travel-book/`（來源說明見該資料夾的 `README.md`）。

- 介面顏色由 `assets/travel-book/style-tokens.css` 的 `--tb-*` 變數提供，`index.html` 的 `--ui-*` 對應到這些變數；小冊列印頁（`#bkcss`）不使用這些變數。
- `brand/logo-horizontal-clear.*` 是從 `logo-horizontal` 裁掉底部色塊、去背後的版本。
- `icons/` 由 `app-icon-1024` 裁成滿版正方形後產生；maskable 版本把圖縮到 82% 並以模糊底圖補邊。
- 素材原始插畫為 AI 產生後拆分，放大不等於提高印刷解析度。

## 資料版本（schema）

每份行程都存有 `schema` 版本號（目前是 2）。要改資料結構時：

1. 把 `index.html` 裡的 `SCHEMA` 加一。
2. 在 `MIGRATE` 加一個步驟，鍵是「從哪一版升上來」，例如 `2:t=>{ /* 把舊欄位改成新欄位 */ }`。
3. 新欄位的預設值寫在 `normalize()`。

讀取或匯入時會依序跑完升級步驟。如果瀏覽器裡有比程式還新的資料（例如舊的快取頁面打開了新版存的資料），程式會暫停儲存並提示重新整理，避免蓋掉資料。

## 小冊範本

範本設定集中在 `TEMPLATES`（名稱、紙色、封面選項，以及載圖、裝飾等掛鉤），CSS 寫在 `#bkcss` 裡的 `.bk.tpl-<id>` 底下。新增範本時加一筆設定、寫對應的 CSS 即可。
